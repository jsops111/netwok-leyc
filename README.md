# network-check

网络线路检测与展示平台 —— 秒级拨测、交换机/防火墙/服务器采集、
配置定时备份、防火墙策略查看、带外硬件监控(iDRAC)、事件追踪、告警推送。

```
   拨测线路 ──┐
              │
   交换机 ────┤
   路由器 ────┼──→ 阈值判定 ──→ 事件(开/关) ──→ Telegram / Webhook
   防火墙 ────┤                    │
              │                    └──→ 监控大屏 / 事件报告
   服务器 ────┘
   (SSH,不装 agent)

   交换机/路由器/防火墙 ──→ 配置定时备份 ──→ 版本历史 + 变更 diff
   防火墙 ────────────────→ 策略快照 ─────→ 规则查看 + 命中统计
```

技术栈:Django 6 + DRF + PostgreSQL 17 + Celery/Redis + pysnmp/paramiko;
前端 Vue 3 + TypeScript + Naive UI + ECharts,赛博朋克风格。
**深色 / 亮色两套主题**,顶栏右上角切换,选择记在浏览器里。

**全站需要登录**(大屏也是),自带用户管理和**可选的**两步验证。

部署看 [DEPLOY.md](DEPLOY.md)。改代码看 [CLAUDE.md](CLAUDE.md)。

## 能做什么

### 线路拨测

六种协议,**频率可低到 1 秒**:

| 协议 | 测什么 | 能算出 |
|---|---|---|
| ICMP | 通断 | 延迟、丢包率、抖动 |
| TCP | 握手时间 | 延迟、抖动(连上立刻关,对被测服务无害) |
| UDP | 端口可达 | 延迟(无响应按通计,强度弱于 TCP) |
| HTTP / HTTPS | 状态码 + 响应内容 | 延迟、**证书剩余天数** |
| DNS | 指定 DNS 服务器的解析 | 延迟、解析结果是否被劫持 |

丢包率和抖动来自**一组包**(每次发 N 个),不是单次探测。抖动用相邻包延迟差的
平均绝对值(IPDV),不是 ping 的 mdev —— 后者对"稳定但偏高"的线路给不出区分度。

判定分三档:`正常` / `劣化`(通但超阈值) / `中断`。
每条线路有延迟、丢包、抖动各自的警告线和严重线。

### 设备采集

三条通道,按型号选主通道 + 降级通道:

| 通道 | 拿得到 | 拿不到 |
|---|---|---|
| **SNMP** v2c/v3 | 接口流量/错包、CPU、内存、温度、电源风扇 | FortiGate 的会话细节、策略命中 |
| **SSH CLI** | SNMP 没暴露的东西 | 需要按型号+版本写解析器,最脆 |
| **REST API**(FortiGate) | 会话数、策略命中、HA 成员、License 到期 | 只实现了 FortiOS |

在册型号(需求点名必须支持的四款):

- `C9300-48T`、`C9300-24T` — Catalyst 9300
- `C9200L-24T-4G` — 温度/电源在这款上常采不到,画像里声明为可选项
- `FortiGate-401F` — 推荐 `API 主 + SNMP 降级`

不在册的型号回落到「通用」画像,仍能采通断、接口流量、运行时长。
型号画像在 `backend/netcheck/devices/profiles.py`,加型号通常只改这一个文件。

### 服务器监控

**通过 SSH(22 端口)采集,不用在机器上装任何东西。**支持 **Linux / 类 Unix**
和 **VMware ESXi** 两种,加服务器的时候在「系统类型」里选 —— 两者走的采集命令
完全不同,**选错了指标会全是空的而且不报错**(ESXi 上没有 `/proc/stat`
也没有 `/proc/meminfo`,但 shell 跑得通,采集器会认为"连上了、命令跑完了")。

#### Linux

| 采什么 | 怎么采 |
|---|---|
| CPU 使用率 / iowait | `/proc/stat` 两拍 jiffies 相减 |
| 内存 / Swap | `/proc/meminfo`,按 **MemAvailable** 算(页缓存不算已用) |
| 磁盘 | `df`,按**占用率最高的那个挂载点**判,告警里带挂载点名字 |
| 负载 | `/proc/loadavg`,阈值按**每核**判 |
| 网络流量 | `/proc/net/dev`,只统计主网卡(默认路由那块) |
| 基本信息 | 主机名、发行版、内核、核数、内存总量、运行时长 |
| 进程 Top | `ps` 按 CPU 排前 5 —— 回答"是谁在吃 CPU" |
| 连接数 | `/proc/net/tcp` 里 ESTABLISHED 的条数 |

**全部读 `/proc`,不解析 `top` / `free` 的输出** —— 后者的格式随发行版、
版本和 locale 变,而 `/proc` 的格式是内核 ABI。

负载按每核判是有意的:64 核的机器 load 8 很闲,2 核的 load 8 已经跑不动了,
用同一个绝对阈值必然错一边。

#### VMware ESXi

ESXi 没有 Linux 那套 `/proc`,走 `esxcli` 和 `vim-cmd`(SSH 要先在
「主机 → 管理 → 服务」里把 **TSM-SSH** 起来,默认是关的)。

| 采什么 | 怎么采 |
|---|---|
| CPU 使用率 | `vim-cmd hostsvc/hostsummary` 的 `overallCpuUsage` ÷ 主频池 |
| 内存 | 同上的 `overallMemoryUsage` ÷ `memorySize` |
| 数据存储 | `esxcli storage filesystem list`,按最满的那个判,**bootbank 不计入** |
| 网络流量 | `esxcli network nic stats get`,主上行口按累计字节自动挑 |
| 基本信息 | 主机名、ESXi 版本、硬件型号、几路几核几线程、内存总量、运行时长 |
| 虚拟机 | `esxcli vm process list` —— 运行中 / 已注册各几台,以及都有谁 |

三处和 Linux 不一样,页面上都标了出来:

- **CPU 第一拍就有数**(hostd 自己在算,不用等两拍 jiffies 相减)
- **没有负载 / iowait / Swap** —— ESXi 不提供,显示成"ESXi 不提供"而不是 `—`,
  免得看着像采集坏了。负载阈值对 ESXi 主机不生效
- **bootbank 不算磁盘** —— 那两个引导分区天生就用到八九成,算进来的话
  每台 ESXi 一加进来就撞穿严重线,而那不是个能行动的告警

页面在 `/servers`:一台一块面板,左边基本信息 + CPU/内存/磁盘/负载四条仪表,
右边趋势图(流量 / CPU / 内存 / 负载切换),展开看挂载点(ESXi 是数据存储)
明细、网卡列表、进程 Top(ESXi 是虚拟机清单)。

### 带外硬件监控(iDRAC)

**走 Redfish(HTTPS,只读),回答的是「这台机器本身会不会坏」。**

和「服务器监控」是两件事:那边走 SSH,看的是系统忙不忙、盘满没满;
这边看的是**物理部件** —— 哪块盘、哪条内存、哪个电源、RAID 卷、风扇、
逐点温度、硬件事件日志。

这些东西**在操作系统里通常一点症状都没有**:一块正在 SMART 预警的硬盘、
一个已经掉了电的冗余电源,SSH 上去什么都看不出来。所以两边覆盖不重合,
一台机器可以两边都加(用「对应的服务器」把它们连起来),
也可以只有其中一边(裸金属常常只有 iDRAC)。

| 采什么 | 判什么 |
|---|---|
| 物理盘 | 已经异常的 / **SMART 预警**(还在跑但快坏了)/ SSD 剩余写入寿命 |
| RAID 卷 | 降级 / **冗余度归零**(卷还是"正常",但再坏一块盘就丢数据) |
| 电源 | 模块异常 / **输入电压 0**(线掉了,机器照跑) |
| 内存条 | 逐条状态(固件不支持时退回汇总值,页面上会说明) |
| 风扇 | 状态 + 转速(报百分比的机型会标出单位) |
| 温度 | 逐个探头 + 进风温度 + **同机两颗 CPU 的温差** |
| 硬件日志 | SEL,**按时间窗过滤** |

三条判据是平台自己的,**不照抄 iDRAC 的 status 位**:

- **同机温差。**iDRAC 的温度严重线通常是 100℃(CPU 的绝对上限),所以一颗
  散热坏了、比同机另一颗高 20℃ 的 CPU 在它眼里是"正常"的。而进风温度不高
  却两颗差很多 = 就是这一颗的问题(风道堵了 / 硅脂干了),不是机房热
- **SMART 预警单独报。**等 `Health` 变红时盘通常已经掉了
- **SEL 按窗口算。**硬件日志不会自动清,一台跑了几年的机器上留着很早以前的
  记录很正常。直接数总数会得到一个永远不变的大数字 —— 一条永远都在的红
  等于没有红

三个不能混的三态:

| | |
|---|---|
| 部件**读不到状态** | 单独一档,不算正常也不算故障。并进"正常"会让一台权限配错的 iDRAC 在大屏上显示成一片绿 |
| **机械盘**的剩余寿命 | 不显示。它没有这个概念,Redfish 上返回 0 —— 显示成 0% 会让人以为一排盘都写光了 |
| 刚加进来**还没轮到采** | 单独一档,不算失联。算成故障会让新加的机器先红一阵子 |

页面在 `/idrac`:顶部六格(总数 / 严重 / **带外失联** / 警告 / 状态读不到 /
尚未采集,失联和严重**分开**——前者查网络凭据,后者去机房换件),
中间是全场部件总览,下面每台一张卡片(温度、同机温差、功耗、五类部件计数、
未恢复告警),点「明细」看逐块盘 / 逐条内存 / 逐个探头 / 硬件日志。

⚠ 采集间隔**最小 60 秒**:BMC 是一颗很弱的处理器,打太勤会把它自己拖慢,
严重时管理界面登不进去 —— 而那正是出事时要用的东西。

### 配置定时备份

交换机 / 路由器 / 防火墙的配置定时拉回来存档。

**一行一个配置版本,不是一行一次备份。**交换机的配置一年可能只改三次,
而备份一天跑一次 —— 按"每次一行"存,一年三百多行里只有三行有信息。
所以配置没变就不新增版本,只把最新那行的「最后确认」往后推。
**于是版本列表天然就是一份变更历史,行数 = 真实变更次数。**

比对之前会**清洗掉每次导出都变但没有意义的行**(Cisco 的
`! Last configuration change`、`Current configuration : N bytes`、
`ntp clock-period`,FortiOS 的 `#conf_file_ver=`)。不清洗的话每天备份
都是"变更过",而真正被人改配置的那一天就藏在噪声里。
**存的是原始文本**,下载下来能直接回灌。

- 通道:FortiGate 有 API Token 走 `config/backup`(能直接回灌的备份文件),
  其它走 SSH。**和采集通道无关** —— 一台用 SNMP 采指标的交换机照样能备份配置
- 每台设备各自的间隔(默认 24 小时)和保留版本数(默认 20)
- 配置变更会记一条 `info` 级事件;**备份失败记 `warning` 级并推送** ——
  一个悄悄坏掉的备份等于没有备份,而这件事没有任何别的症状
- 页面在 `/backups`:版本列表带 `+3 -1` 的变更行数、unified diff、全文、下载。
  **对比基准可以换** —— 和上一版比是"这次改了什么",和三个月前那版比是
  "从那次故障之后这台设备被动过什么",复盘时问的是后者

**顺带检查「配置有没有未保存」** —— `show running-config` 备下来的配置可能
一次断电就不存在了,因为有人改完忘了 `write memory`:

- 比对 running-config 和 startup-config(只有 Cisco 有这个概念,FortiOS 改完即存)
- 三态:有未保存改动 / 已保存 / **未检查**。「未检查」不显示成「已保存」——
  那是替设备做一个没验证过的保证
- 给的是**差异行数 + diff 本身**,页面上点开就能看差了哪几行 ——
  比给一个不透明的布尔靠得住
- 有未保存改动会记一条 warning 事件并推送(设备重启这件事没人会提前通知你)
- 代价是每次备份多取一份配置、时间约翻倍,所以是单独一个开关

### 防火墙策略查看

看 FortiGate 上**现有**的规则,存成快照定时刷新(默认 30 分钟)。

```
顺序 | ID | 名称 | 源接口/地址 | 目的接口/地址 | 服务 | 动作 | NAT | 启用 | 命中 | 最后命中
```

- **顺序就是语义**,默认按设备上的先后排(防火墙先匹配先生效),
  要按命中数排得显式点
- **命中计数只有 REST API 拿得到**。「这条规则从来没命中过」是能直接拿去
  删规则的结论,所以页面把三种情况严格分开:命中过 / 确实从未命中 /
  **不知道**(SSH 通道没有计数)—— 把"不知道"当成"没命中"会让人删掉一条
  其实在用的规则
- 同步是**全量替换**:设备上删掉的规则在这边也会消失。留着一条现实中已经
  不存在的规则比没有这个页面更危险
- 设备连不上时页面照样能看,只是标明"数据截止于什么时候" ——
  防火墙不通恰恰是最需要查规则的时候

**映射(端口映射 / 目的 NAT)** —— 和策略同一次同步拉回来。

策略表回答"允不允许",映射表回答**"外面的 1.2.3.4:443 到底进到内网哪台机器
的哪个端口"**。后者完全不在策略表里:一条入站策略的目的地址里只有一个
`web-vip` 这样的名字。所以两处都显示:

- **策略表的「目的」列**里,目的地址下面直接跟一行 `↳ tcp/1.2.3.4:443 → 10.0.0.5:8443`
- **单独一个「映射」面板**,列出这台防火墙上的全部映射,可以搜、可以筛

(注意策略表里那个 `NAT` 列是**源** NAT —— 出去的时候换成出口地址,
和这里说的映射不是一回事。)

两个单独标出来的东西:

| | 含义 |
|---|---|
| **整机映射** | `portforward` 关着 = 外网地址的**所有端口**都通到内网那台机器上。暴露面比端口映射大得多,而在列表里它和一条只映射 443 的规则长得几乎一样 |
| **没有策略引用** | 没有任何策略的目的地址引用它 —— 配了但不生效,可以清理 |

端口为空时页面显示**「所有端口」而不是空白或 0**:空白看着像"没配好",
0 是一个具体的端口号,而真相是"每个端口都进去"。

「没有同步到映射」**不等于「这台防火墙没有映射」** —— SSH 的
`show firewall vip` 可能没跑成、API 可能权限不够。页面上说的是前者。

**规则审计** —— 防火墙评审要回答的四个问题,页面上直接给答案:

| 发现 | 含义 | 要不要命中统计 |
|---|---|---|
| **过宽的放行规则** | 源/目的/服务都是任意的 accept。等于这对接口之间没有防火墙 | 不要 |
| **永远匹配不到的规则** | 同一接口对上被前面的 any-any-any 挡住了(先匹配先生效) | 不要 |
| **放行但不记日志** | 出事之后查不出来源,而放行规则最需要留痕 | 不要 |
| **从未命中过的规则** | 可以清理的候选 | **要** |

判定上的自律:只判「启用 + 放行」的规则(停用的不生效,any-any-any 的**拒绝**
规则正是兜底该有的写法);空数组当成"任意"(没写这一维就是不限制);
地址名精确比较(`all-servers` 不是"任意")。

影子规则只判**绝不会误报的那一种**(被 any-any-any 挡住)。更一般的判定要做
地址段包含和端口区间运算,**没做也不猜** —— 告诉工程师"这条规则没用"而它
其实在用,比不告诉他糟得多。

点某一类发现能直接把它筛到规则表里。**导出 CSV** 带上当前筛选和风险标记,
带 UTF-8 BOM(否则 Excel 打开中文是乱码)—— 评审要把这张表交给安全的人。

### 邻居发现与拓扑

**「这个口对面接的是谁」** —— 排障时问的第一个问题。`show lldp neighbors` /
`show cdp neighbors` 的 SNMP 版本,**LLDP 和 CDP 两套都采**(纯 Cisco 环境里
往往只开了 CDP,只采一套会让"有些口对面是空的"被当成"没接线")。

- 每个口对面是谁、什么型号、管理地址、对端的哪个口
- **受管链路**:两端都在这个平台管着的链路会合并成一条(同一条物理链路
  两端各上报一次),并标注是不是**双向确认**。单向确认要单独看 ——
  可能对端没开 LLDP,也可能我们把邻居挂到了错误的本地口上
- **邻居变了会记事件并推送**:对端换人、对端消失、对端 chassis id 变了
  (换上一台同型号同 hostname 的备机)—— 通常意味着有人动了线
- 本地口解析不出 ifIndex 时标成「口未解析」,**不挂到一个猜的口上** ——
  一份错的拓扑比没有拓扑危险

### MAC / IP 地址查找

**「这台机器插在哪个口上」** —— 交换机排障问得最多的一句话。

- 输入 MAC(`aa:bb:cc:dd:ee:ff` / `aabb.ccdd.eeff` 都认)或 IP,选设备,现场查
- 查 IP 是两段式:先在选中的设备里找 ARP 拿到 MAC(**只有三层设备有**),
  再拿 MAC 去二层设备上找口
- **按需查,不定时采集**:MAC 表大而易变,存下来的是一份过期的表,
  而排障要的是"现在在哪儿"
- **桥端口号不是 ifIndex。**翻不出 ifIndex 时结果里明确写出"这是桥端口号" ——
  照着错的结果去拔线,拔的是别人的

### 配置合规基线

跑在**已经备份下来的配置**上,不需要新采集。19 条规则(Cisco / FortiOS)。

**备份的 diff 告诉你「变了什么」,基线告诉你「缺了什么」** —— 后者更容易
被忽略:telnet 一直开着、community 还是 `public`、口令是明文、日志没往外送、
NTP 没配所以日志时间是错的。这些没有任何症状,直到出事或者审计。

- 每条发现都带**为什么是问题**和**该敲什么命令**,以及命中的**具体行号**
- 区分「配错了」和「从来没配」
- **没有规则的厂商 / 没有备份的设备明确显示「未检查」** ——
  那不等于合规。一个 0 条问题的设备如果其实没检查过,这一页就是在骗人

### 事件

**一行一次异常**,不是一行一条日志:

```
类型 | 对象 | 详情 | 发生时间 | 恢复时间 | 持续 | 推送状态
```

- 连续 N 次失败才开事件,连续 M 次正常才关 —— 否则瞬时丢包会把告警刷爆
- 同一来源同一类型**同时只有一条未恢复事件**(数据库部分唯一索引兜底)
- 级别从警告升到严重时**升级现有事件并重推**,不新开一条
- 未恢复的事件持续时长实时计算

二十二种事件类型,顶部统计的五项是:断线 / 丢包 / 延迟 / 抖动 / 异常。

服务器侧多了三种:服务器失联 / 磁盘空间不足 / 负载过高(CPU、内存和设备共用)。
备份侧的三种是**瞬时事件** —— 配置发生变更 / 配置备份失败 / 配置未保存:
它们"发生了就是发生了",没有"还在持续"这回事,所以开即关、
不出现在「未恢复」列表里,但照样在事件表里占一行。

### 告警推送

- **Telegram** — Bot Token + Chat ID,支持群组话题和反代地址
- **Webhook** — 留空发标准 JSON;填模板可对接钉钉/企微/飞书

过滤在推送侧做(级别下限、事件类型、监控类),事件该记的照记。
静默窗口防 flapping 轰炸。每次推送的结果都记在推送记录里 ——
"告警到底发出去没有"这个问题必须能回答。

### 账号与权限

全站要登录。**两步验证是自愿绑定的,平台不强制** —— 但要有这个能力,
所以管理后台里做全了:

- **TOTP 两步验证** —— 扫码绑定标准验证器 App(Google Authenticator /
  微软 Authenticator / 1Password 都行)。绑定要输一次码确认才算成功:
  跳过这一步的话,手机时间不同步这类问题要等到下次登录才暴露,
  而那时人已经被自己锁在门外了
- **恢复码** —— 十个一次性码,只在生成那一次显示明文(库里存哈希)。
  手机丢了时它是唯一能自己进来的路径
- **管理员可强制解绑** —— 恢复码也丢了时的最后一条路,这个动作会记进审计
- **登录审计** —— 成功和失败都记,而且分得开"密码错"和"验证码错":
  前者可能是有人在试口令,后者通常是自己手机时间不对
- **失败锁定** —— 按用户名和 IP 各记一份计数。只按 IP 记的话,
  出口 NAT 后面一个人输错会锁掉整个办公室

TOTP 密钥和设备凭据同一级别对待:落库用 `NETCHECK_ENCRYPTION_KEY` 加密。

## 十个页面

页面右上角可以切换**深色 / 亮色**。深色是默认 —— 这个平台首先是挂在墙上的
大屏;亮色给白天在工位上看的人。两套都是整套的,不是给某个组件加个媒体查询:
颜色全部收在 CSS 变量里,`frontend/scripts/theme_check.py` 会检查有没有漏网的
硬编码颜色,以及对比度和色盲分离度是否达标。

### 监控大屏 `/`

- 顶部:断线/丢包/延迟/抖动/异常**次数** + 线路可用率
- 中部:**一个监控类一张大图**,延迟/丢包/抖动切换;断线区间画成红带,
  阈值画成虚线;图右侧是该组线路的当前值清单
- 底部:交换机/防火墙卡片 —— CPU/内存/温度趋势、会话数、活动接口带宽
- 第二排还有服务器的状态分布,和**「N 台设备的配置备份失败」**那一行 ——
  一个悄悄坏掉的备份没有任何别的症状,只能主动把它显示出来

一次刷新只打三个接口(统计 5s / 图表 10s / 设备 30s),页签隐藏时自动暂停。

### 服务器 `/servers`

一台一块面板。左边是**基本信息**(地址、发行版、内核、核数、内存)加
CPU / 内存 / 磁盘 / 每核负载四条仪表条,再加当前流量和一条 sparkline;
右边是**趋势图**,流量 / CPU / 内存 / 负载切换着看。

展开一台还能看:每个挂载点的占用(按满的程度排)、网卡列表(标出主网卡和
虚拟口)、进程 Top 5、以及 iowait / Swap / 进程数 / ESTABLISHED 连接数。

**算不出来的值一律显示 `—`。**刚加进来的服务器第一拍没有 CPU 使用率
(要两拍 `/proc/stat` 相减),页面上会直接写出这句话 —— 显示 0% 的意思是
"这台机器很闲",那是假数据。

### 配置备份 `/backups`

上面是设备列表:备份结果(成功/失败/从未备份)、间隔、保留版本数、
最后一次的错误。有**「测通道」**(取一份配置回来但不存版本)和
**「立即备份」**两个按钮。

下面是选中设备的**版本列表**:首次出现时间、版本哈希、`+3 -1` 的变更行数、
最后确认时间和确认次数、行数和大小。每个版本可以看 diff、看全文、下载。

### 防火墙策略 `/policies`

上面按防火墙一行:策略总数、允许/拒绝、**过宽**、**无日志**、**从未命中**、
同步时间和间隔。

中间是**规则审计**面板 —— 四类发现各一格,点一下就把那一类筛到下面的表里;
展开明细能看到每条规则为什么被挑出来(影子规则会写明是被哪一条挡住的)。

下面是规则表,可以按名称/地址/服务/备注搜,按动作和启用状态筛,
按命中数或流量排序,三个开关(只看从未命中 / 只看过宽 / 只看无日志),
以及**导出 CSV**。「风险」那一列直接标出过宽和无日志。

点「详情」看单条的全部字段,包括设备返回的原始记录
(FortiOS 的策略有上百个字段,表格里只展示常看的十几个)。

最下面是**映射**的三个数(总数 / 整机映射 / 没有策略引用)和一个入口 ——
完整的映射表在单独一页 `/mappings`。

### 防火墙映射 `/mappings`

和策略页同一个结构:上面选防火墙,下面是那台的完整映射表 ——
名称、外面看到的地址端口、进到哪里、类型、被哪些策略引用、走的哪条通道。
可以搜(名称 / 外部地址 / 内部地址 / 备注)、按类型筛,
两个开关:只看整机映射 / 只看没有策略引用的。

映射和策略是**同一次同步**拿回来的,所以这一页的「立即同步」和策略页那个
是同一个动作。

### 端口面板图

在 `/interfaces` 选中一台设备,接口表上方会画出这台设备的**端口面板** ——
按型号排出和实物一样的样子,鼠标移上去看端口信息,点一下在下面的表里定位到它。

| 颜色 | 含义 |
|---|---|
| 绿 | 通 |
| 红 | **管理是开的但链路 down** —— 这才是"该通没通" |
| 灰 | 人为关闭(admin down) |
| 深灰 | 状态没采到 |

⚠ **人为关闭是灰色不是红色。**48 口交换机上一半的口是人为关掉的,
全画红的话满屏是红,真正断掉的那一个就淹在里面了。

⚠ **画错的面板比没有面板危险** —— 有人会照着它去机房拔线。所以:

- 端口的**数量和名字来自设备本身**,型号画像里只声明几何(几排、列优先还是
  行优先、哪几个是上行口)。插了扩展模块的交换机图上会自动多出那几个口
- **面板号不是 ifIndex**(`Gi1/0/24` 面板上印的是 24,ifIndex 可以是任何数)
- 认不出的型号**仍然画,但明确标着「这是按接口名排的示意图,不是真实面板布局」**;
  照规格图推、没上过实机核对的排布也会标出来。找物理口请以**接口名**为准 ——
  名字是印在设备上的,位置不是
- 不在物理面板上的口(Vlan / Port-channel / Loopback)列在图下面,不会被悄悄丢掉

### 设备接口 `/interfaces`

大屏上只有每台设备"最忙的 6 个口",而巡检、排障、交维要的是**完整的一张
接口表**:ifIndex、接口名和描述、管理/运行状态、协商速率、双向速率、
利用率仪表条、错包增量、最后状态变化,以及每个口的「纳入监控」开关。

三个筛选:搜接口名/描述、**只看异常**、只看 up 的。还有 **CSV 导出**(带筛选)。

两处刻意的口径:

- **「速率成色」那一列**显示 64 位 / 32 位。ifHC* 采不到时退回 32 位计数器,
  而 48 口千兆满速时它约 34 秒回绕一次 —— 60 秒间隔算出来的速率是噪声,
  可它看起来是个正常数字。不标出来就会有人拿它去排查一个不存在的流量问题
- **「异常」不含 admin down。**48 口交换机上一半的口是人为关掉的,那不是故障;
  筛的是 `admin up 但链路 down` 或者本周期新增了错包

### 邻居与拓扑 `/topology`

三块:**地址查找**(MAC/IP → 哪个口)、**邻居发现**(按设备一行,标出通道 ——
走 API/SSH 的设备采不到邻居,"0 条"不等于"没接线")、**受管链路**
(合并双向,标出单向确认的)。下面是选中设备的邻居明细,可搜、可筛
「只看受管对端」/「只看变化过的」,可导出 CSV。

### 配置合规 `/compliance`

按设备一行:结论(严重/警告/提示 各几项,或者「未检查」及原因)、
通过几条规则、基于哪一份备份。展开看每条发现:为什么是问题、该敲什么命令、
命中在第几行。有严重项的设备默认展开。

### 事件记录 `/events`

上面是汇总(总数、未恢复、平均持续、累计故障时长)和四个排行
(按类型、出事最多的线路、出事最多的设备、出事最多的服务器),
下面是可筛选分页的事件表。支持认领和重推。

### 配置中心 `/config`

五个 tab:检测线路 / 监控类 / 网络设备 / 服务器 / 通知渠道。

每一类都有**「测试」按钮** —— 这是这一页最有价值的东西:
配错凭据是最常见的问题,不测的话要等一个采集周期再去大屏上找,
中间任何一环出错都分辨不出是哪儿的问题。开了备份的设备还多一个
**「测备份」**,它的报错是指向性的(需要 enable / 权限不足 / 型号不支持)。

### 管理后台 `/manage`

四个 tab,其中**只有「我的安全」对所有登录用户开放**,另外三个要管理员:

| tab | 谁能看 | 干什么 |
|---|---|---|
| 用户管理 | 管理员 | 增删改、启用/停用、重置密码、强制解绑两步验证、清除失败锁定 |
| 我的安全 | 所有人 | 改自己的密码;绑定/解绑两步验证、重新生成恢复码 |
| 登录审计 | 管理员 | 谁在什么时候从哪个 IP 登的、失败的是密码还是验证码 |
| 系统信息 | 管理员 | **磁盘用量与增长估算**、**数据保留天数(可改)**、PG/调度器连通、各表占用 |

有两条守卫是后端兜的,不是靠前端藏按钮:不能停用/降级/删除**自己**,
也不能把**最后一个管理员**停掉 —— 那会让所有人都进不来。

## 部署 / 更新 / 卸载

下面每一段都是**整段复制粘贴就能跑**的,不用改里面的值。
下面用 `/data/netwok-leyc` 做部署目录,换地方就把路径一起改掉。

### 一、首次部署

**第 1 步:拉代码**

```bash
mkdir -p /data && cd /data
git clone https://github.com/jsops111/netwok-leyc.git
cd /data/netwok-leyc
ls docker-compose.yml backend frontend      # 这三个都在,说明拉全了
```

仓库是公开的,不需要账号密码。要是提示输用户名,说明仓库被改成私有了,
用 GitHub 的 personal access token 当密码。

服务器上装了 git 才能这么拉。没有的话:`dnf install -y git`(Amazon Linux /
CentOS)或 `apt install -y git`(Debian / Ubuntu)。

**第 2 步:生成配置和密钥**(只做一次,整段粘贴)

```bash
cd /data/netwok-leyc
cp -n .env.docker.example .env.docker

# 四个密钥自动生成写入。只用 openssl,不需要装 python 的 cryptography
SECRET=$(openssl rand -base64 48 | tr -d '\n')
FERNET=$(openssl rand -base64 32 | tr '+/' '-_' | tr -d '\n')
PGPASS=$(openssl rand -base64 24 | tr -d '/+=\n')
RDPASS=$(openssl rand -base64 24 | tr -d '/+=\n')
sed -i "s|^DJANGO_SECRET_KEY=.*|DJANGO_SECRET_KEY=${SECRET}|"           .env.docker
sed -i "s|^NETCHECK_ENCRYPTION_KEY=.*|NETCHECK_ENCRYPTION_KEY=${FERNET}|" .env.docker
sed -i "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=${PGPASS}|"           .env.docker
sed -i "s|^REDIS_PASSWORD=.*|REDIS_PASSWORD=${RDPASS}|"                 .env.docker
chmod 600 .env.docker
grep -c CHANGE_ME .env.docker    # 输出 0 才算改干净了
```

⚠ **`.env.docker` 里的 `NETCHECK_ENCRYPTION_KEY` 要单独备份。**
丢了它,库里所有 SNMP community / SSH 口令 / API token / 两步验证密钥都解不出来,
光有数据库备份没用。

**第 3 步:构建并启动**

```bash
cd /data/netwok-leyc
docker compose --env-file .env.docker up -d --build
```

报 **`compose build requires buildx 0.17.0 or later`** 的话,说明这台机器的
buildx 太旧或没装 —— **那不是"还在构建",是直接失败退出了**。改用下面这三条,
它们走老构建器,不经过 buildx:

```bash
cd /data/netwok-leyc
DOCKER_BUILDKIT=0 docker build -t netcheck-backend:latest  ./backend
DOCKER_BUILDKIT=0 docker build -t netcheck-frontend:latest ./frontend
docker compose --env-file .env.docker up -d --no-build
```

首次构建 3-5 分钟(拉基础镜像 + 装依赖),会一直有输出滚动。

**第 4 步:确认起来了,拿管理员密码**

```bash
cd /data/netwok-leyc
docker compose --env-file .env.docker ps
# -sS 而不是 -s:-s 会把 "connection refused" 也一起吞掉,服务没起来时
# 你只会看到一个空行,看着像"命令没反应",实际上是根本没连上
curl -sS http://127.0.0.1:18120/api/health/; echo

# 全站需要登录。第一个管理员是首次启动自动建的,密码只打印这一次:
docker compose --env-file .env.docker logs backend | grep -A3 "管理员账号已创建"
```

`db` `redis` `backend` `frontend` 是 `healthy`、`worker` `beat` 是 `Up`,
并且 health 返回 `"status": "ok"`,才算真的好了。

然后打开 `http://<服务器IP>:18120/` → 用 `admin` + 上面那个密码登录 →
**先去「管理后台 → 我的安全」改掉初始密码** → 配置中心建监控类和线路。

### 二、更新到新版本

```bash
cd /data/netwok-leyc
git pull origin main
docker compose --env-file .env.docker up -d --build
docker compose --env-file .env.docker ps
curl -sS http://127.0.0.1:18120/api/health/; echo
```

同样,报 buildx 错误就换成:

```bash
cd /data/netwok-leyc
git pull origin main
DOCKER_BUILDKIT=0 docker build -t netcheck-backend:latest  ./backend
DOCKER_BUILDKIT=0 docker build -t netcheck-frontend:latest ./frontend
docker compose --env-file .env.docker up -d --no-build
```

**数据不会丢** —— 库和 Redis 在命名卷里,只要不加 `-v` 就一直在。
数据库迁移是 backend 容器启动时自动跑的,不用手动 `migrate`。

改了阈值、线路、设备这些**配置不用重启**,页面上保存即生效。
只改了 `.env.docker` 的话不用 `--build`,`up -d` 就行。

### 三、停止 / 卸载

```bash
# 停止服务,数据全部保留,随时 up -d 回来
cd /data/netwok-leyc
docker compose --env-file .env.docker down
```

```bash
# 一键彻底卸载:容器 + 数据卷 + 本项目镜像 全删
# ⚠ 历史样本、事件记录、用户账号会全部消失,不可恢复
cd /data/netwok-leyc
docker compose --env-file .env.docker down -v --rmi local --remove-orphans
docker image rm postgres:17-alpine redis:8-alpine 2>/dev/null
docker volume ls | grep netcheck        # 应该没有输出了
```

想连基础镜像和构建缓存一起清干净,再加一条(会影响这台机器上别的项目):

```bash
docker system prune -a
```

`.env.docker` 不会被删。**要重装同一套数据的话必须留着它**(加密密钥在里面);
彻底不要了再 `rm -f .env.docker`。

### 常用运维命令

```bash
cd /data/netwok-leyc
# 采集出问题优先看 worker
docker compose --env-file .env.docker logs -f worker
docker compose --env-file .env.docker logs --tail 100 backend

# 只重启采集进程
docker compose --env-file .env.docker restart worker beat

# 线路多了扛不住:加 worker 副本(beat 绝对不能多起,它是定时器)
docker compose --env-file .env.docker up -d --scale worker=3

# 备份数据库(记得同时备份 .env.docker)
docker compose --env-file .env.docker exec -T db \
  pg_dump -U netcheck network_check | gzip > netcheck-$(date +%F).sql.gz
```

机房没有外网、故障排查、离线打包这些看 [DEPLOY.md](DEPLOY.md)。

## 磁盘与数据保留

这是个数据采集平台,**涨起来的就是磁盘**。所以管理后台的「系统信息」里
第一块就是磁盘:

- 总量 / 已用 / 可用 + 使用率仪表条(80% 转黄、90% 转红)
- 数字取自跑 Docker 的那台机器 —— 容器里 `/` 是 overlay 挂载,
  它的 `statvfs` 返回的就是承载 `/var/lib/docker` 的宿主机磁盘,
  和在宿主机上 `df -h` 看到的一致
- **每天新增多少**:按当前线路配置推算(每条线路每天写 86400÷间隔 行),
  不是实测增速;单行字节数由样本表实际大小反推
- **保留期内稳定占用**:清理跑起来之后原始表会稳定在这个量级

保留天数**在页面上直接改**(管理后台 → 系统信息 → 数据保留),
改完下一次清理任务就按新值执行,不用重启任何进程 ——
磁盘告急这件事往往发生在半夜,那时候改环境变量 + 重启容器通常不方便。

| 数据 | 默认 | 说明 |
|---|---|---|
| 原始秒级样本 | 48 小时 | **磁盘的主要消费者**,告急时先缩它 |
| 服务器 / 设备样本 | 同上 | **没有降采样表**,所以能看的历史跨度就是这个值 |
| 1m 桶 | 7 天 | ≤2 天跨度的图查它 |
| 5m 桶 | 30 天 | ≤14 天跨度的图查它 |
| 1h 桶 | 永久(0) | 一条线路一年 8760 行,唯一能回答"去年这条线怎么样" |
| 事件 | 永久(0) | 设了天数也只删已恢复的 |
| 推送记录 | 30 天 | "告警到底发出去没有"的审计材料 |
| 登录审计 | 180 天 | 谁在什么时候登过这台机器 |
| 配置备份 | 每台 20 个版本 | 不按天算,按**变更次数**算(配置没变不新增版本)。在设备配置里改 |
| 防火墙策略 | 只有当前快照 | 每次同步全量替换,不留历史 |

图表按时间跨度自动选粒度:≤2h 原始点 → ≤2d 1m → ≤14d 5m → 更长 1h。
**这只对线路生效** —— 设备和服务器的样本没有降采样表(一天几千行,和秒级
拨测不是一个量级),它们的图直接查原始点,所以想看一周的服务器趋势要先把
「原始秒级样本」的保留期调大。

配置备份的全文存在库里(`netcheck_devicebackup`),一份几十 KB 到几 MB ——
它会出现在「系统信息」的表占用排行里。磁盘紧的时候先调小设备的「保留版本数」。

**粗粒度的保留不能短于细粒度的**,后端会挡住这种配置:细桶比粗桶留得久时,
查粗桶的那个跨度就是一片空白 —— 图上表现为"最近有数据、更早反而没有"。
